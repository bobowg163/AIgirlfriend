## Purpose

为 AI 女友应用提供快递物流查询能力，用户可通过对话发送快递单号，系统自动查询并返回物流状态。

## ADDED Requirements

### Requirement: 快递单号识别与提取
系统 SHALL 在用户消息中检测快递查询意图，自动提取快递单号。

#### Scenario: 用户发送含快递单号的消息
- **WHEN** 用户消息包含快递关键词（如"快递"、"物流"、"到哪了"、"包裹"）且包含 8-30 位数字或字母数字混合的单号
- **THEN** 系统 SHALL 自动识别并提取单号，调用快递查询工具

#### Scenario: 用户消息无单号
- **WHEN** 用户消息包含快递关键词但未包含可识别的快递单号
- **THEN** 系统 SHALL 回复友好提示，询问用户快递单号，不发起 API 调用

#### Scenario: 用户消息非快递查询
- **WHEN** 用户消息不包含快递关键词且无快递单号特征
- **THEN** 系统 SHALL 不进行快递查询，正常进行对话

### Requirement: 快递物流信息获取
系统 SHALL 调用第三方快递查询 API 获取物流轨迹，并以自然语言向用户播报。

#### Scenario: 物流查询成功
- **WHEN** 快递单号有效且 API 返回物流信息
- **THEN** AI SHALL 以女朋友口吻回复物流状态，包含：当前状态（如"已派送"）、最新中转站、预计送达时间，并附带关心话语（如"你的快递马上到啦，记得签收哦~"）

#### Scenario: 物流查询失败
- **WHEN** API 调用超时、返回错误码或单号不存在
- **THEN** AI SHALL 回复友好提示（如"小薇查不到这个快递的信息呢，可能单号有误，宝宝再确认一下~"），不暴露技术错误细节

#### Scenario: 不支持的快递公司
- **WHEN** 查询 API 不支持该快递公司的单号格式
- **THEN** AI SHALL 提示用户该快递暂不支持查询，建议用户自行查看

### Requirement: 多单号连续查询
系统 SHALL 支持在一次对话中查询多个快递单号。

#### Scenario: 用户发送多个单号
- **WHEN** 用户消息中包含两个及以上可识别的快递单号
- **THEN** 系统 SHALL 依次查询每个单号，并在回复中逐条列出物流状态
